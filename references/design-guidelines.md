# Product and UI design guidelines

## Start with the user journey
Identify user, goal, entry point, key actions, decision points, success state, and failure/recovery paths. Design the critical journey before decorating screens.

## Visual system
Define:
- Typography scale and readable line lengths.
- Spacing scale and layout grid.
- Color roles (background, surface, text, muted, border, primary, success, warning, danger).
- Radius, border, elevation, and focus styles.
- Responsive breakpoints based on content needs.

Use design tokens or centralized variables. Avoid arbitrary one-off values.

## Quality bar
- Clear hierarchy and predictable navigation.
- Strong contrast and readable typography.
- Responsive layouts that work on narrow screens.
- Useful empty, loading, error, validation, success, and disabled states.
- Semantic HTML and keyboard access.
- Motion is purposeful, restrained, and respects reduced-motion preferences.

## Avoid
- Generic dashboard layouts when the product does not need a dashboard.
- Gratuitous gradients, glassmorphism, excessive shadows, and decorative animation.
- Placeholder copy that survives into the final product.
- Buttons that do nothing or controls with unclear outcomes.
- Copying a reference design without considering the product's users and content.

## Design review
Check hierarchy, consistency, responsiveness, keyboard navigation, contrast, content density, and state coverage. Do not claim formal accessibility compliance without a proper audit.
